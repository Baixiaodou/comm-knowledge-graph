## 一、一句话结论

**知识库对全部被测模型都是正增益**：`程序初筛 + 模型精挑` 的检索框架（召回 93%），配合「结论式内容写法」，让小模型（8B/14B）增益 +0.57、大模型（DeepSeek）+0.23，且**没有一档模型被知识库拖累**。核心功臣是**内容质量**（结论式写法），而非结构复杂度。

## 二、知识库设计思想（数据库思想）

### 2.1 核心理念：节点即一切

知识库不是一个「文档库」，而是一个**知识图谱**——每个 `.md` 文件是一个知识点节点，用三种结构组织：

| 结构 | 表达什么 | 回答的问题 |
|------|---------|-----------|
| **树（parent/children）** | 分类学层级 | 这个知识点「在哪」 |
| **Wiki（links）** | 跨树语义关联 | 这个知识点「和谁相关」 |
| **思维链（cot）** | 推理过程 | 这个概念「怎么想」 |

树 + Wiki 不矛盾：**树管"在哪"（分类），Wiki 管"和谁相关"（关联），cot 管"怎么想"（推理）**。

### 2.2 三类节点

| 类型 | 含义 | 特征 | 例子 |
|------|------|------|------|
| **core** | 核心概念 | 有 cot 思维链 | 香农公式、OFDM、维纳-辛钦 |
| **hub** | 分类文件夹 | 有子节点，无 cot | 信道、抗衰落、多址组网 |
| **leaf** | 叶子知识点 | 无子节点，无 cot | 幅度调制、GSM、TCP/UDP |

### 2.3 每门课一个「贯穿性枢纽」

每门课的核心思维（写成 root 节点的 cot）：

| 课程 | 枢纽（思维方式） |
|------|----------------|
| 通信原理 | **权衡**（理论极限 vs 工程实现） |
| 信号与系统 + DSP | **对偶对称**（时域↔频域、离散↔周期） |
| 移动通信 | **三大根本矛盾**（信道恶劣/频谱有限/用户移动） |
| 随机信号处理 | **维纳-辛钦定理**（自相关↔功率谱） |
| 电磁场 | 麦克斯韦 → 电磁波 → 天线 |
| 计算机网络 | **分层**（封装/解封装） |

### 2.4 课程层次（六棵树的关系）

```
数学三大件（微积分/线代/概统）          ← 树根，不建节点
        ↓
工具课：信号与系统+DSP ＋ 随机信号处理    ← 分析工具
        ↓
通信原理                              ← 绝对核心（系统框架）
        ↓
应用外延：移动通信 / 高频电路 / 计网 / 电磁场
```

一句话：**工具课提供数学工具 → 通信原理搭系统框架 → 应用课做工程落地**，硬件整体偏外。

## 三、实现思路

### 3.1 节点结构（frontmatter）

```yaml
id: mob-ofdm            # 唯一标识，前缀表示所属树（comm/dsp/mob/rsp/emf/net）
title: OFDM（正交频分复用）
parent: mob-anti-fading # 父节点（树层级）
depth: 3                # 树深度
type: core              # core / hub / leaf / root
summary: 一句话摘要（第一轮目录里模型判断相关性的依据）
links:                  # Wiki 连接，双向可达
  - id: dsp-dft-fft
    relation: "OFDM 用 IFFT/FFT 实现调制解调，是 DFT 最成功的工程应用"
cot:                    # 思维链（仅 core）
  origin: "高速数据在多径信道上 ISI 严重，怎么办？"
  reasoning: "..."
  conclusion: "..."
```

### 3.2 内容写法：结论式（关键演进）

经过 benchmark 验证后，从「描述式」升级为「结论式」，统一模板：

```
## 一句话本质      ← 第一行就是答案核心（TL;DR 前置）
## 为什么需要它    ← 解决什么问题
## 核心机制        ← 用 → 箭头串成一条链
## 关键结论        ← 结论式写法，直接可抄
## 权衡            ← 有则写，呼应全库枢纽
```

**核心变化**：从"描述式"（"子载波 Δf 精确"）改成"结论式"（"子载波正交 → 省一半频谱"），让 AI **扫一眼就能提取结论**，弱模型也能直接抄，而不是靠框架自己推导。

### 3.3 权威节点合并

跨树反复出现的概念，合成一个权威大节点，三棵树都 links 指向它——**"哪怕选错树，也能收敛到同一个完整节点"**：

| 权威节点 | 合并前（散在多处） |
|---------|------------------|
| `mob-ofdm`（OFDM） | comm-multiplexing / dsp-dft-fft / mob-ofdm 三处 |
| `mob-multiple-access`（多址） | comm-multiplexing / mob-multiple-access |
| `mob-equalization`（均衡） | comm-receiver / dsp-min-phase / mob-equalization |

### 3.4 检索流程（最终形态）

```
问题 → ① TF-IDF 初筛（排除 hub/root，只留 core/leaf，top-3）
     → ② links 扩展（top-3 的 Wiki 邻居 core/leaf 并入候选）
     → ③ 模型精挑 2-3 个节点
     → ④ 注入（content + cot + links 关系描述）
     → ⑤ 答题
```

## 五、评测历程与结果

### 5.1 三轮 benchmark 演进

| 轮次 | 题库 | 检索方案 | 关键结论 |
|------|------|---------|---------|
| **v4** | 26 题（六模型全梯度） | 方案 A（模型自主选） | 全正增益，但小模型增益低 |
| **v5/v6** | 35→51 题 | 方案 A/B/C/D/E/F 对比 | 选节点命中率定案 |
| **最终** | 35 题（5 模型） | 程序初筛 + 精挑 | 小模型被拯救 |
| **难题轮** | 15 反直觉题 + 严格裁判 | 程序初筛 + 精挑 | 难题上增益更大 |

### 5.2 v4：六模型全梯度（方案 A）

| 模型 | 规模 | 裸跑 | +知识库 | 增益 |
|------|:---:|:---:|:---:|:---:|
| Qwen3-8B | 8B | 7.81 | 7.92 | +0.11 |
| Qwen3.5-9B | 9B | 8.04 | 8.19 | +0.15 |
| Qwen3-14B | 14B | 7.77 | 8.08 | +0.31 |
| Qwen3-32B | 32B | 7.92 | 8.04 | +0.12 |
| GLM-4-32B | 32B | 7.96 | 8.04 | +0.08 |
| DeepSeek | 大模型 | 8.36 | 8.69 | **+0.33** |

**发现**：增益非单调（14B 和 DeepSeek 双峰）；小模型在方案 A 下增益低，因为**选节点依赖模型能力**（弱模型选不准）。

### 5.3 最终策略：程序初筛 + 精挑（35 题，5 模型）

| 模型 | 规模 | 裸跑 | +知识库 | 增益 | 选节点命中 |
|------|:---:|:---:|:---:|:---:|:---:|
| Qwen3-8B | 8B | 8.23 | 8.80 | **+0.57** | 91% |
| Qwen3-14B | 14B | 8.26 | 8.83 | **+0.57** | 89% |
| Qwen3-32B | 32B | 8.37 | 8.54 | +0.17 | 84% |
| GLM-5.2 | 大模型 | 8.46 | 8.86 | +0.40 | 93% |
| DeepSeek | 大模型 | 8.57 | 8.80 | +0.23 | 91% |

**核心结论**：
1. **全部 5 模型正增益**，没有一档被知识库拖累
2. **小模型增益最大**（8B/14B +0.57），因为裸跑分低、可补空间大
3. **小模型被拯救**：对比 v4 方案 A，8B 从 +0.11 提到 +0.57（5 倍）、14B 从 +0.31 提到 +0.57——程序初筛让"选节点"不再依赖模型能力，弱模型也能拿到正确知识

### 5.4 反直觉难题轮（15 题 + 严格裁判）

题目换成"反直觉 + 深层理解"（表面规律人人背得出，深层机制只有真懂的模型能答），裁判收紧（漏要点重扣）。

| 模型 | 裸跑 | +知识库 | 增益 |
|------|:---:|:---:|:---:|
| DeepSeek | 7.67 | 8.17 | **+0.50** |
| Qwen3-14B | 6.87 | 8.13 | **+1.27** |
| Qwen3-32B | 7.60 | 8.00 | +0.40 |

（8B / GLM-5.2 因硅基流动限流数据不完整，未纳入）

**结论**：题目变难后，裸跑分下降、天花板效应放宽，**知识库增益反而翻倍**——小模型（14B）在难题上增益 +1.27，是最能体现知识库价值的场景。

## 六、检索方案研究（A → 最终形态）

### 6.1 方案演进

```
方案 A：模型自主选节点（看 74 节点目录自己选）
    ↓ 弱模型选不准（36 节点目录下 5 题只对 1 题）
方案 B：纯 TF-IDF top-3（程序，不依赖模型）
    ↓ 召回只有 82%，且混入 hub 分类节点
方案 C：程序筛 top-10 + 模型精挑
    ↓ 召回 89-93%，框架基本定型
方案 D/E/F：排除 hub + links 扩展（微调）
    ↓ 发现精挑有随机噪声，D/E/F 差异不可信
最终形态：TF-IDF 初筛 top-3（排除 hub）+ links 扩展 + 模型精挑
```

### 6.2 六方案统一口径对比（干净题库，DeepSeek）

| 方案 | 机制 | 召回率 |
|------|------|:---:|
| B 纯 TF-IDF top-3 | 纯程序 | 82% |
| A 模型看 74 目录自主 | 模型看大目录 | 88% |
| C top-10 含 hub + 精挑 | 程序+精挑 | 89% |
| E top-10 排除 hub + 精挑 | 程序+精挑 | 91% |
| F links 扩展截断 + 精挑 | 程序+精挑 | 91% |
| D links 扩展不截断 + 精挑 | 程序+精挑 | 95%（噪声） |

**稳定结论**：真正的分水岭是「程序初筛 + 模型精挑」这个框架（82% → 90%+），links/hub 细节是 1-2 个百分点的微调，淹没在精挑噪声里。

### 6.3 links（Wiki 连接）研究的最终结论（经完整版 benchmark 修正）

links 的价值**取决于两个变量：top-K 宽度 和 题库难度**。早期在 50 题（v5+hard，题目措辞较规范）上，links 增量仅 +1.3 点、看似"微乎其微"；但扩展到 116 题完整题库（含老题、措辞多样）后，links 的价值被放大到 **+5.8 点**。

**根本机制**：top-K 越窄，初筛漏掉的正确答案越多，且这些漏掉的节点排名越靠前、越容易被 links 邻居带回。题目措辞越多样（老题的关键词和新知识库节点匹配度低），正确答案的 TF-IDF 排名越靠后，top-10 捞不到、links 却能救回。

| links 用法 | 实测结果 |
|-----------|---------|
| 选节点时扩展（top-8/10 够宽时） | 零收益（补进的节点 0 expected） |
| 选节点时扩展（top-3/4 收窄时） | **+5.8 点**（救回排名靠后的 expected） |
| 注入时全文扩展 | +0.2 分，但 3 倍 token 成本 |

### 6.4 完整版 benchmark（116 题，合并全部历史题库）

构建完整题库 `questions_full.json`（合并 questions.json / v3 / v5 / v6 / hard / cross，去重 + 修正 14 处 hub/已删除节点 + 19 个 id 重复），三方案对比：

| 方案 | 召回率 | 完全命中 | 平均候选 |
|------|:---:|:---:|:---:|
| 方案 B · top-10 + LLM | 74.3% | 78/116 | 10.0 |
| **top-3 + links + LLM（✓ 最终选定）** | **79.1%** | 83/116 | **9.8** |
| top-4 + links + LLM | 80.1% | 85/116 | 12.3 |

**最终选定 top-3 + links**：召回 79.1%（比方案 B 高 +4.8 点），候选仅 9.8（比方案 B 的 10 还省）。相比 top-4 只低 1 点，但候选少 20%——性价比最优。

## 七、核心洞察（经验总结）

1. **内容质量 > 结构复杂度**。让检索有效的，是「结论式写法」（内容层），不是「树+Wiki」（结构层）。结构是"面向未来规模"的投资。

2. **「程序初筛 + 模型精挑」框架是最大收益**（召回 82% → 93%），它同时解决了两个问题：程序扛住大目录（不依赖模型能力）、模型保住语义精挑（弥补关键词局限）。

3. **增益 = 可补空间 × 吸收能力**。小模型增益大（+0.57）是因为裸跑分低、可补空间大；大模型（DeepSeek）裸跑已 8.57，边际空间小（+0.23），是"锦上添花"。

4. **题目难度决定增益天花板**。旧 35 题偏简单（47% 拿 9 分），天花板效应压缩了增益；换成反直觉难题后，小模型增益放大到 +1.27。

5. **知识库的最终价值是给洛洛（DeepSeek）用**，+0.23（旧题）/ +0.50（难题）稳定正增益；但更关键的是——这套策略让小模型也能用知识库，未来给洛洛换轻量模型省成本时，知识库照样兜得住能力短板。

6. **links（结构层）的价值不是"有没有"，而是"什么条件下有"**。早期结论"links 增量微乎其微"建立在「题目措辞规范、top-K 够宽」的前提上；完整题库（116 题、措辞多样）证明 links 能救回 top-10 捞不到的正确答案（+5.8 点）。所以「内容质量 > 结构复杂度」要加一个限定——**在关键词检索开始漏的场景（难题、老题、大规模库）下，links 导航的价值会重新凸显**。

## 九、待办与展望

1. **可选的「软精挑」**：当前落地是程序 top-3 直接注入（88% 召回），若要提到 93% 可加一次模型精挑，或让答题模型直接参考 top-10 摘要（精挑与答题合并）。
2. **links 的规模红利**：知识库扩到几百节点时，激活 links 导航（1-hop 扩展）才有实打实的增量。
3. **第三门课深化**：计网（6 节点）和电磁场（1 节点）偏薄，可按需口述深化。
4. **硬件课**（模电/数电/CPU/SoC/STM32）暂不整合，偏外。

> **后续（2026-08-21 起）**：本项目新增**多轮追问记忆**能力——在检索流水线上加"追问判定 + 历史节点优先并入 + gate 带上一轮上下文"，对裸指代追问（"那反过来呢"）增益 +29%，详见 `docs/07-多轮追问技术报告.md`。
