## 1. 评测理念：不数连接，考实战

**连接多 ≠ 质量好。** 把所有节点互连一遍，数字好看但全是噪音。

业内三个主流范式，我们取其三合一：

| 范式 | 来源 | 测什么 | 自动化程度 |
|------|------|--------|:---:|
| 任务驱动评估 | RAGAS 标准 | 真实问题回答质量 | 需人工出题 |
| LP-Measure | KGGen 论文 | 图内部一致性 | 全自动 |
| 防腐化检测 | LLM Wiki 社区 | 矛盾/孤立/来源 | 全自动 |

## 2. 三层评测体系

### 第一层：防腐化检测（全自动，每次入库跑）

`tools/kb_lint.py`

| 检查项 | 含义 |
|--------|------|
| 矛盾检测 | "OFDM.md 说子载波必须正交 → FFT.md 说可以有频偏" → ⚠️ 冲突 |
| 来源追溯 | 核心断言能否追溯到 raw/ 原始素材？没有来源的可能是 AI 编的 |
| 孤立节点 | 既无 links 又无 children 的节点 → 可能是垃圾 |
| 事实 vs 推理 | "多径导致 ISI"（事实）vs "所以均衡器必须用 MMSE"（推理）→ 标记差异 |
| 结构完整性 | parent 存在性、depth 正确性、links 目标有效性 |

### 第二层：LP-Measure 一致性测试（全自动，定期跑）

**原理**：从知识图谱中随机删掉一些 links → 用剩下的图结构预测被删的 links → 预测越准 = 内部一致性越高。

```
1. 从 nodes/*.md 抽取全部 links
2. 随机删 20%
3. 把删掉后的图（树结构 + 剩余links）给 LLM
4. LLM 预测：哪些节点之间应该有关联
5. 恢复率 = 正确预测 ÷ 被删数量 → 一致性得分
```

打比方：随机抹掉你和小王的连线，问 AI"根据剩下的关系网，这俩人认识吗？" 猜对了说明图内在逻辑自洽；猜错了说明本来是乱连的。

### 第三层：任务驱动 benchmark（需人工出题，核心评测）

`tools/kb_benchmark.py --full --questions questions.json`

```
准备 N 道题（涵盖你学过的所有领域）
    ↓
用你的知识库去回答这 N 道题
    ↓
四个维度打分：

1. 检索成功率 —— 树+Wiki 导航找到正确节点的比例
2. 答案忠实度 —— LLM 回答是否严格基于知识库内容（有没有编造）
3. 答案正确性 —— 和标准答案对比
4. 覆盖率 —— 知识库能回答多少题
```

## 3. 题库分层设计（L1-L4）

**关键洞察：benchmark 必须测难题。** 简单定义题两种方案都能答，看不出差距；综合/模糊题才是 v2 打传统 RAG 的地方。

| 层级 | 题型 | 示例 | v2 预期增益 |
|:---:|------|------|:---:|
| **L1 基础** | 单概念定义 | "什么是循环前缀？" | 0-5% |
| **L2 应用** | 概念在场景中使用 | "CP 在 LTE 中怎么设计的？" | 5-15% |
| **L3 综合** | 跨模块关联 | "OFDM + MIMO 为什么能提升频谱效率？" | **15-30%** |
| **L4 模糊** | 开放性问题 | "通信系统的设计哲学是什么？" | **20-40%** |

**重点测 L3+L4**——这是 v2 存在的原因。评测时按层分别统计提升，报告才能说清楚「v2 对基础题无提升，对综合题提升 ~25%」。

题库来源：**用户的保研面试题**（大量 L3/L4 综合追问），整理成结构化 JSON：

```json
{
  "id": "comm-001",
  "level": 3,
  "question": "OFDM + MIMO 结合为什么能提升频谱效率？",
  "answer": "（标准答案，来自知识库/面试经验）",
  "expected_nodes": ["comm-ofdm", "mobile-mimo", "comm-modulation"],
  "subject": "通信原理"
}
```

## 4. 模型对比设计

### 核心对比矩阵

| 维度 | 配置 A | 配置 B | 对比意义 |
|------|--------|--------|----------|
| 模型 | DeepSeek 裸跑 | DeepSeek + 知识库 | 大模型本身知识 vs 知识库增量 |
| 模型 | Qwen 1.5B 裸跑 | Qwen 1.5B + 知识库 | **小模型本身弱，更能体现知识库价值** |
| 裁判 | Qwen-Max（强模型） | — | 独立评判，避免自评偏差 |

### 为什么加 Qwen 1.5B？

- DeepSeek 本身很强，知识库增量可能被"模型自身知识"掩盖
- Qwen 1.5B 本地小模型**几乎没学过这些专业知识**，知识库的注入效果会非常明显
- 两组对比形成对照：**知识库对大模型 vs 小模型的增益差异**

### 评测流程

```
题库（30-50 题，L1-L4 混合）
        │
        ├─→ DeepSeek 裸答 → 答案 A₁...Aₙ
        ├─→ DeepSeek + 知识库 → 答案 B₁...Bₙ
        ├─→ Qwen 1.5B 裸答 → 答案 C₁...Cₙ
        └─→ Qwen 1.5B + 知识库 → 答案 D₁...Dₙ
                │
                ▼
        Qwen-Max 逐题评判（四维度打分）
                │
                ▼
        汇总 → 分层统计 → 可视化报告
```

## 6. 关键决策记录

| 决策 | 理由 |
|------|------|
| 题库以 L3/L4 为主 | 简单题两种方案都能答，测不出差距 |
| 用 Qwen-Max 当裁判 | 独立强模型，避免"自己答自己评" |
| 加 Qwen 1.5B 小模型组 | 小模型知识弱，知识库增益更明显，形成对照组 |
| LP-Measure 定期跑 | 全自动、无人工、测图的内在逻辑自洽性 |
| 若 L3/L4 提升 <10% | **立刻止损**，不做后续投入 |
