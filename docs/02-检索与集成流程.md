# 02 检索与集成流程

> 创建：2026-08-07 / 更新：2026-08-09

## 1. 检索流程：树 + Wiki 不矛盾

它们是**两个维度**：

| | 树（parent/children） | Wiki（links） |
|---|---|---|
| 关系类型 | 分类学层级（OFDM **是**一种调制技术） | 语义关联（OFDM **用到**FFT） |
| 检索作用 | **缩小范围**：导航到正确分支 | **横向扩展**：拉到相关知识 |

```
用户问："OFDM里循环前缀怎么对抗多径？"
        ↓
Step 1  树导航：读 tree.json → 通信原理 > 调制解调 > OFDM
        → 定位节点 comm-ofdm
        ↓
Step 2  读节点 comm-ofdm.md：
        - 读它的 content（核心理解）
        - 读它的 links → 发现连到 mobile-multipath, dsp-fft
        ↓
Step 3  沿 links 扩展（1-hop）：
        - 读 mobile-multipath.md 的多径部分
        - 读 dsp-fft.md 的FFT部分
        ↓
Step 4  检测 cot 字段 → comm-ofdm 有思维链 → 带上
        ↓
Step 5  组装：树路径 + 节点内容 + 关联节点 + 思维链 → 喂给 LLM 回答
```

**树负责"你在哪"，Wiki负责"还有谁相关"。** 就像查字典：先看目录找到章节，再看"参见xxx"跳到相关条目。两步不打架，反而是互补。

### 给 LLM 的 context 组装顺序

```
1. tree.json 骨架（让 LLM 知道知识全貌）
2. 目标节点 content
3. links 关联节点内容（1-hop）
4. cot（若有）
```

## 2. 新知识集成流程

```
一段新文本进来（口述 / 文章 / 笔记）
    ↓
LLM 分析：这是关于什么的？
    ↓
两种情况：
    ├─ 匹配到已有节点 → 内容合并，检查是否需要更新 links
    └─ 全新概念 → 创建新节点，确定 parent（挂在树哪个位置）
         ↓
    LLM：这个新节点和哪些已有节点有关？
         ↓
    已有节点 links ← 加上新节点
    新节点 links ← 加上所有关联节点
         ↓
    LLM 判断：这是核心概念吗？
    是 → 生成 cot 写入
    否 → 跳过
```

改动量：**创建/修改 1-3 个 md 文件**。不需要重建索引、不需要数据库迁移。

## 3. 完整使用工作流（本地）

```
你复习 + 看笔记
    ↓
你口述长语音 → 转文字发我
    ↓
我提取：你的思维线（不是知识点罗列，是你怎么理解这门课的脉络）
    ↓
我们讨论这条线 → 你补充/修正
    ↓
我从思维线里挑一个核心主题
    ↓
你针对这个主题再做一轮口述 → 转文字
    ↓
我再提取 → 再讨论 → 再展开子主题
    ↓
像树一样递归展开，深度 2-3 层
    ↓
每次展开写入 knowledge-v2/nodes/ 对应节点
```

**核心是：你的认知路径、你的权衡视角、你觉得什么是枢纽、你用什么类比去理解。** 知识点嵌在思维线里，作为支撑，而不是主体。
