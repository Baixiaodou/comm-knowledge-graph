# 模糊大问题粗粒度匹配技术报告（fuzzy_hub_rag）

> 模糊宽泛大问题（"移动通信都有哪些关键技术？"）直接命中具体知识点会失焦。本插件在
> 检索入口前做**大小问题路由**：模糊大问题 → 命中 hub 枝干节点 → 注入「主题域总览 +
> 统领子主题列表」→ AI 输出总览框架 + 分支列举 + 引导追问；用户追问分支时由追问记忆
> 插件（followup_rag）承接，落到具体 leaf/core 精细回答——**先给地图、追问再钻到街道**。
>
> 方法：**benchmark-first**——先建「大小点分类」专项 benchmark（数据 + 评测框架），
> 再把候选路由方案做成可插拔策略逐一实验，用准确率/命中率/调用成本数据选胜者，
> 胜者才固化为线上插件。不预设方案。

---

## 问题

1. **判定难**：模糊大问题 vs 具体小问题如何区分？「问题简短 + 开放式问法词表」判定被
   实验否决（不靠谱）；且句法开放的具体问题（"载波同步、位同步、帧同步分别解决什么
   问题"）与真模糊问题句式几乎一样。
2. **选点难**：hub 层 TF-IDF 排序不可靠（知识库设计之初就因同样原因在初筛中排除
   root/hub）——但 hub 路由必须面对它。
3. **闭环**：模糊轮回答后，追问轮必须能承接上下文落到具体分支，不能断裂。

## 方法（benchmark + 五策略）

**专项 benchmark（40 题）**：20 道模糊大问题（覆盖 7 树 + root 级极泛 + 跨树，`questions_fuzzy.json`）
+ 从 116 题题库固定 seed 抽 20 道对照组（具体知识点问题）。Part A 测大小点分类准确率，
Part B 测 hub 选点 hit@1/hit@2。**标准答案标注**：DeepSeek 3 轮独立选 hub（temp 0.7）→
轮内投票（仅取 ≥2 票）→ 人工复核（F15 多数派错标被修正：emf 树无 hub 应落 root）。

| 策略 | 路由 | hub 选点 | LLM 调用 |
|---|---|---|---|
| S1 | 纯 TF-IDF 双池分流（floor/margin 网格） | TF-IDF top-2 | 0（基线） |
| S2 | TF-IDF 分流 + 临界 LLM 确认 | 确认后 TF-IDF top-2 | 在局时 1 次 |
| S3 | 同上 | **LLM 从全部 19 hub 语义选 1-2** | 在局时 1 次 |
| S4 | 同上 | LLM 从 TF-IDF top-5 候选选 | 在局时 1 次 |
| S5 | 全 LLM 判定（每问必调） | 全量 19 hub 选 1-2 | 每问 1 次（上界） |

## 核心结论 1：TF-IDF 双池分流不可靠（S1-S4 共同瓶颈）

| 策略（最优配置） | Part A 准确率 | 大问题召回 | hit@1 / hit@2 | LLM 调用 |
|---|---|---|---|---|
| S1 纯 TF-IDF | 77.5% | **60%（漏 8/20）** | 40% / 50% | 0 |
| S2 +临界确认 | 77.5% | 55% | 35% / 45% | 13 |
| S3 +全量选点 | 77.5% | 55% | 50% / 55% | 13 |
| S4 +top-5 候选 | 80% | 60% | 40% / 50% | 13 |
| **S5 全 LLM** | **97.5%** | **95%** | **85% / 90%** | 40 |

- S1 阈值网格（floor×margin 3×3）怎么调都在 57.5~77.5%——**结构性失败**；
- S2/S3/S4 加 LLM 兜底只提升 0-2.5 个百分点：**TF-IDF 把真大问题判成小问题后，
  LLM 根本没机会被调用**（60% 召回是共同天花板）。

## 核心结论 2：选点必须全量语义选，TF-IDF 候选会漏

S4（top-5 候选）判对题内 hit@2=83% < S3（全量 19）91%——候选池漏选担忧实测成立。

## 核心结论 3：判定判据 = 主语是否点名具体概念（prompt v2）

- v1（仅句式）→ 对照组 17/20 误判（把"点名多个具体技术问分别/对比"也当大问题）；
- v2 加核心判据：**点名具体概念/定理/技术 → 小问题；主语是主题域/课程/模块全貌 → 大问题**
  （附正反例）→ 对照组误判 **0/20**；
- 已知边界案例：F16「多用户怎么共享同一个频谱？」（"怎么"规则误伤）——个例未过度特化。

## 核心结论 4：TF-IDF 只配做粗筛，不配做精选（补充实验）

k=2-12 扫描（含 root）：**候选召回 k=6 即 100%**（20/20 正确 hub 全部落入 top-6）；
排除 root 后 k=2 掉到 60%（4/20 题的正确答案就是 root，**root 必须保留**）。

混合方案（LLM 判大小 + TF-IDF top-k + LLM 从候选选点，k=4~8 真调 API）：

| 配置 | 分类 A | hit@1 | hit@2 |
|---|---|---|---|
| k=4 | 90% | 70% | 80%（候选召回 90% 是硬伤） |
| k=5 | 100% | 75% | 85% |
| **k=6** | 95% | 80% | **90%** |
| k=7 | 100% | 75% | **90%** |
| k=8 | 95% | 75% | 85% |
| **S5 全量 19** | 97.5% | **85%** | **90%** |

k=6/7 与全量 hit@2 持平（90%），hit@1 全量仍最高（85%）→ 线上采用 **k=6 候选**
（路由清单 1327→150 字，省 ~69%）；`fuzzy_hub_candidate_k` 可调大或 ≥19 回退全量。

## 关键取舍（实测排除/验证的选项）

| 取舍 | 结果 |
|---|---|
| 候选清单砍 summary | A/B 无差别（hit@2 均 17/20）→ 砍（省 ~270 token/次） |
| 输出砍 reason | 线上形态 20 题复测 hit@1/hit@2 与实验完全一致 → 砍（省 ~50 token/次） |
| root 注入瘦身（leaf 层去 summary） | 7338→5056 字；last_ids 保持全量，追问闭环不受影响 |
| 合并进 `_refine` 一次调用（0 额外调用） | 侵入正常检索路径（与独立开关约束冲突），未采纳，记录备查 |
| 追问轮跳过路由（省 1 次调用） | 无追问 benchmark 验证，未采纳，记录备查 |
| 追问闭环 | 端到端模拟验证：模糊轮 last_ids=hub 子孙 → 追问轮历史 9 节点全并入候选池 → 落到具体节点（followup_rag 零改动） |

## 线上形态

```
用户提问 → [闲聊拦截] → LLM 路由（TF-IDF top-6 候选清单 + 大小问题判定 + 选 1-2 hub）
  ├─ HUB：注入 hub 内容 + 统领子主题标题树 → 总览+分支+引导追问；last_ids=子孙 core/leaf
  └─ LEAF：原版精确检索（TF-IDF → links → 精挑 gate → 注入 top-3）
```

- 每 RAG 问题 +1 次 LLM 调用（~1000 token）；HUB 命中后跳过精挑 gate（净增 ≈ 0）；
  闲聊不触发；路由失败自动降级走原路径；
- 独立开关 `fuzzy_hub_enabled`（关 = 行为与现状完全一致）；
- 服务器日志观测关键字：`模糊大问题路由`。
