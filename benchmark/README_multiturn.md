# 多轮追问 Benchmark 使用说明

## 一、文件清单

| 文件 | 作用 |
|---|---|
| `benchmark/multiturn_questions.json` | 追问题库（44 组 / 156 轮，含 dependency 档位 + expected_nodes） |
| `tools/gen_multiturn_benchmark.py` | 题库生成脚本（解析 `个人对话常用.txt` + 人工标注 + 补 D4/D1 + 真实负例） |
| `tools/validate_multiturn.py` | 题库校验（expected_nodes 是否都为 core/leaf 节点 + 分档分布） |
| `tools/eval_followup.py` | 评测脚本（baseline vs followup，分档指标 + 闲聊前置过滤 + 多变体对比） |
| `tools/analyze_gain.py` / `analyze_negatives.py` | 增益归因 / 负例误检定位 |
| `tools/mine_negatives.py` | 从洛洛真实日志挖「技术→闲聊/换话题」负例候选 |
| **`tools/multiturn_rag/followup_rag.py`** | **追问记忆插件（定稿）**：`FollowupRAG`（判定/合并/上下文）+ `Session`（每用户状态，一行对接线上） |
| `tools/test_followup_rag.py` | 插件一致性自测（插件 vs 评测内联逻辑，156 轮 0 差异） |

## 二、题库结构

```json
{
  "_meta": {"subject": "...", "note": "档位说明", "created": "..."},
  "dialogues": [
    {
      "id": "mt-01",
      "topic": "频域采样与周期延拓",
      "source": "个人对话常用 | 洛洛真实日志 | 构造",
      "subject": "DSP",
      "kind": "positive | negative",
      "turns": [
        {"q": "问题文本", "dependency": "first|D1|D2|D3|D4|D5|chitchat", "expected": ["dsp-dft"]}
      ]
    }
  ]
}
```

### dependency 档位（依赖程度谱系）

| 档 | 含义 | 判定 | 依赖历史 |
|---|---|---|---|
| `first` | 首问 | 每组第 1 轮 | 独立检索 |
| `D1` | 裸指代 / 极短追问 | ≤8 字 + 指代词（"那反过来呢"） | **100% 依赖** |
| `D2` | 短追问 | ≤15 字（"那混叠呢"） | 强依赖 |
| `D3` | 中等追问 | 16~25 字 | 中等 |
| `D4` | 长自包含追问 | >25 字，完整重述上下文 | 弱依赖 |
| `D5` | 新话题（负例） | 换主题 | 零依赖，不该复用历史 |
| `chitchat` | 闲聊（负例） | 非技术 | 不该触发检索 |

## 三、题库组成（44 组）

- **A 部分（30 组正例）**：`source_raw_data/个人对话常用.txt` 的「主问题 + 追1 + 追2」，每组末尾补 1 条 D1 裸指代；其中 8 组额外补 1 条 D4 长追问（制造长短梯度）
- **B 部分（4 组真实口语化）**：洛洛真实日志（conversation_summaries #97 FM-f³ / #90 香农→白噪声 / #70 线性调制 + journalctl 有色噪声平稳性）
- **C 部分（10 组负例）**：3 条新话题误检（构造）+ 7 条闲聊误检（其中 5 条来自洛洛真实日志：技术问题后表白/聊生活/聊天气等）

## 四、评测方法

### 运行

```bash
# 全量（39 组，gate 模式，约 292 次 LLM 调用）
python tools/eval_followup.py

# 先跑前 12 组快速验证
python tools/eval_followup.py --limit 12

# 只跑插件（省一半 LLM 调用）
python tools/eval_followup.py --mode followup

# 纯 TF-IDF sanity check（0 LLM 调用，验证逻辑）
python tools/eval_followup.py --no-gate --limit 12
```

（用项目根 `.venv` 的 python，或确保 `openai` + `yaml` 已安装）

### 对比对象（唯一变量 = 追问记忆插件）

| 模式 | 检索流程 |
|---|---|
| `baseline`（无插件） | 每轮独立：TF-IDF 初筛 → gate 精挑（无上下文） |
| `followup`（有插件） | 追问判定 → 历史节点并入候选池 → gate 带上一轮上下文 |

### 指标

| 指标 | 定义 | 关注档位 |
|---|---|---|
| **recall@3** | 注入节点 ∩ expected 非空 / 该档轮数 | D1~D4（重点） |
| **漏检率** | gate 判 NONE（不注入）的追问轮占比 | D1~D4 |
| **新话题误用率** | D5 轮注入偏离 expected 的占比 | D5 |
| **闲聊误检率** | chitchat 轮错误触发注入的占比 | chitchat |

## 五、可调旋钮（eval_followup.py 顶部常量）

| 旋钮 | 默认 | 作用 | 调法 |
|---|---|---|---|
| `SIM_THRESHOLD` | 0.15 | 追问判定 TF-IDF 相似度阈值 | 漏检多 → 调低；误判多 → 调高 |
| `REF_BOOST_SIM` | 0.03 | 含指代词时的放宽门槛 | 同上 |
| `SHORT_LEN` | 15 | 短追问字数阈值 | 误判多 → 调低 |
| `HIST_WINDOW` | 1 | 历史节点窗口（轮数） | 跨轮回指漏检 → 加 2 |
| `CAND_CAP` | 10 | 候选池封顶 | gate 挑不准 → 降到 8 |
| `FLOOR_WEIGHT` | 0.1 | 历史节点保底权重 | 历史总被忽略 → 升到 0.2 |
| `TFIDF_TOP` | 5 | TF-IDF 初筛取前 K | 候选池不够 → 加到 8 |

## 六、评测演进记录

### v1.0（naive：所有追问都带历史）
D1 +19%，但 **D2 -5%、D3 -5%**——短追问本身信息完整，带历史被带偏。暴露"三态分类"必要性。

### v1.1（只对强指代/省略式带历史，历史优先）
D1 +19% 保持，D2/D3 负增益消除，净增益 **+3% → +5.9%**。

### v1.2（题库升级：负例 5 → 10，含真实日志闲聊）
D1 +25.8%，净增益 **+7.9%**；闲聊误检率 0.5 → 0.143（7 条里 1 条）。

### v1.3（加闲聊前置过滤，模拟线上 `_is_short_chat`）
**当前版本**：
| 档位 | baseline | followup | 增益 |
|---|---|---|---|
| D1 裸指代 | 0.419 | 0.71 | **+0.291** |
| D2 短追问 | 0.732 | 0.756 | +0.024 |
| D3 中等 | 0.90 | 0.90 | 0 |
| D4 长自包含 | 1.0 | 1.0 | 0 |
| 追问档汇总 | 0.696 | 0.794 | **+0.098** |
| 闲聊(chitchat) | - | - | **误检率 0.0**（7 条全拦） |
| 新话题(D5) | - | - | 独立命中率 0.667 |

### v1.4（变体对比：current vs compound vs clean_compound，全量 44 组）
验证"复合方法（信号+与上轮余弦确认）"和"去语气词"是否有效：

| 档位 | n | current | compound | clean_compound |
|---|---|---|---|---|
| D1 裸指代 | 31 | **0.71** | 0.452 | 0.452 |
| D2/D3/D4 | - | 持平 | 持平 | 持平 |
| 追问档汇总 | 102 | **0.794** | 0.716 | 0.716 |
| **净增益** | - | **+0.098** | +0.020 | +0.020 |
| 闲聊误检率 | 7 | 0.0 | 0.0 | 0.0 |
| 新话题独立命中 | 3 | 0.667 | 0.667 | 0.333 |

**结论：current（宽松版）最优，复合方法和去语气词均无效甚至有害**：
- 复合方法（余弦确认 >0.1）把 D1 从 0.71 砍到 0.45——因为 **D1 裸指代（"那反过来呢"）与上一轮词面本就不重合**（这正是它"裸"的原因），余弦确认误杀真追问。净增益从 +9.8% 掉到 +2.0%。
- 去语气词（clean）无额外帮助，甚至 D5 独立命中从 0.667 掉到 0.333。
- 教训：调研报告的"余弦>0.15 确认"只适用于有核心词重合的追问（D2/D3），**不能一刀切用于 D1**——阈值必须按档位区分，这正说明 benchmark 分档测的价值。

关键结论：
- **闲聊误检率 0**：线上 `_is_short_chat`（短句+无技术词+非指代 → 不检索）在评测里模拟后，7 条真实闲聊全被正确拦截——说明线上机制本身有效，评测必须带上它。
- **D1 增益 +0.291 是插件全部价值所在**（裸指代追问 baseline 只有 42%，带历史后 71%）。
- **D4 长自包含追问 baseline 100%**，插件不该碰（v1.1 曾误判 1 条带历史掉 10 分，加了"呢结尾/强指代"判定后消失）。

## 七、三态判定调研（配套文档）

`项目文档/项目设计/三态判定技术调研报告.md`：11 个开源项目 + 学术文献的"追问/新问题/闲聊"判断手段调研。
核心结论 = **三级级联**：规则层（0 成本，覆盖 60-70%）→ 本地 TF-IDF+LR 分类器（覆盖 ~20%）→ LLM JSON 三态判定（只兜底模糊区 10-20%）。
可落地的 prompt 模板、阈值、误判代价矩阵（"新问题误判追问"代价最高）都在报告 §4。
